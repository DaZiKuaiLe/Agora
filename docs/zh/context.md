# 上下文

上下文设置控制每次生成可使用多少对话历史，以及历史内容接近 token 预算时 Agora 如何处理。

## 上下文窗口

**默认上下文窗口**是 token 预算，不是消息条数。预设范围为 **4K** 到 **1M** token，默认值为 **32K**。

预算包含提供商实际可见的请求内容：系统指令、已启用工具的定义、附件文本或已保存的图片转录，以及当前选中的对话分支。Agora 会在本地估算这些开销，并保留能够完整放入预算的最新消息；完整的工具调用轮次不会被拆开。

聊天底栏中的上下文指示器显示估算用量。由于 tokenizer 和提供商侧格式可能不同，该数字可能与提供商最终返回的 token 统计存在差异。

打开一个已有会话后，顶栏菜单里的**查看上下文**会列出下次发送将交给模型的系统提示和消息（不含输入框草稿）。这是只读审计，不会改写对话。

每个对话都可以在高级设置中覆盖默认上下文窗口。

## 可视化上下文推出

启用**可视化上下文推出**后，当前提供商可见窗口之外的消息会变暗。消息仍保留在对话中；切换分支或增大预算后，它们仍可重新进入模型上下文。

## 上下文压缩

较早的已结束轮次会折成提供商请求里的**一条驻留正文**；最近若干轮仍是原文。原始消息不会被删除。

- **自动压缩**在未压缩原文超过该模型阈值、即将发送时询问。可以先压缩再发，也可以本次不压缩直接发。
- **压缩模型**可指定已启用的专用模型；选当前模型则跟随对话模型。
- **尾部保留原文轮数**（默认 8）是逐字保留的近处窗口。更早且已压缩的轮次只以驻留出现。

之后每次压缩只折刚滑出窗口的原文，并追加为驻留里的新一段；旧段不再送进压缩模型重写。点开上下文指示器，选择**上下文全量优化**，会做工具去细节化并按达阈节奏从原文重写全部驻留。压缩机制变更后，发送下一条新消息前会要求先完成这次优化（可暂缓；完成前不能发送）。

驻留里缺细节时用**搜索本会话**。`query_detail_store` 只用于已归档的工具载荷。

!!! tip
    较小预算可以降低单次请求体积；长对话需要避免把全部旧轮原文都发出去时，使用压缩。

!!! note
    驻留是有损的。不能丢的事实请在会话界面核对原文。
