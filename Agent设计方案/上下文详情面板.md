# 上下文详情面板

本模块给其他项目的 agent 移植用。导出文件名里的 Agora 是本项目这个 agent 的名称，不是协议里的固定词。

这个面板回答的问题是：下一发会把哪些角色、哪些正文交给工作模型。不含输入框草稿，不含正在流式输出的那一层。它是只读审计，不是聊天记录，也不能在这里改历史。投影怎么压、窗口怎么切，见 [上下文压缩](./上下文压缩.md)。

入口在已打开会话的顶栏更多菜单里，菜单项是「查看上下文」。新会话、加载中、分享多选时这项不可用。打开后是全屏。返回键关闭，点外面不关。

## 界面从上到下

1. **顶栏。** 标题「上下文详情」。副标题：「下次发送时将交给模型的原文（不含输入框草稿）」。左边关闭。右边下载；还在加载、或没有数据时不出现。
2. **统计条。** 一块浅底卡片，钉在列表顶。
3. **SYSTEM 块。** 已经拼好的系统提示词：压缩政策、人设、活跃记忆等。空则显示「（空系统提示词）」。
4. **将要发送的消息。** 每条一块，默认全部折叠。展开才出等宽正文。列表回收后，折叠状态按这条的 key 记住。
5. **空历史。** 没有可发送的消息时，系统块下面写「当前没有可发送的历史消息」。系统块仍然在。

加载时居中转圈。失败时居中错误色说明和「取消」。原文大到载不进面板时，说明会话数据没有改动。右侧是淡入的滚动条。

会话、所选模型或窗口预算变了，整页重新算。

## 一块消息长什么样

标题行从左到右：

- 发送勾选。工具结果行没有勾选，左边留出同样的空位。勾选的无障碍名称是「发送这条消息」。
- 角色标题。
- 种类小字。普通用户和普通助手没有种类。
- 这一块的估算 token，形如 `12,345 tok`。
- 助手行和工具调用行还有「API」。点开看这次记下的接口返回原文；正在读、没有记下、可以复制，都在这个小对话框里。工具结果行没有 API。
- 折叠箭头。点标题行展开或收起。

展开后底是浅色，正文等宽。空白显示 `—`。

角色和颜色：

| 行 | 标题 | 底色 |
| --- | --- | --- |
| 系统 | SYSTEM | tertiary 容器 |
| 普通用户 | `#n USER · 轮 k` | 浅色主题浅绿 `#A5D6A7`、字 `#1B5E20`；深色主题 `#2E7D32`、字 `#E8F5E9` |
| 助手 | `#n ASSISTANT` | surfaceVariant |
| 工具调用 | `#n TOOL` | error 容器 |
| 工具结果 | `#n TOOL RESULT` | 同一 error 容器，透明度 0.7 |
| 驻留 | `#n COMPACT SUMMARY` | secondary 容器 |
| 轮整合 | `#n 轮整合` | secondary 容器 |

`n` 是这条在发送列表里的序号，从 1 起。`k` 是导出源路径上的对话回合编号，也从 1 起，不是列表下标。合成出来的驻留行、工具行不标「轮 k」。

种类：

| 行 | 小字 |
| --- | --- |
| 驻留，且正文里能数出至少两段 | 整合段 N |
| 其它驻留 | 压缩摘要投影；若这行本身是旧的压缩胶囊，则写「压缩行」 |
| 轮整合 | 轮整合 |
| 工具调用 | 工具调用 |
| 工具结果 | 工具结果 |
| 后台进程结束那条 | 后台进程通知 |

压缩行和工具行不要做成普通聊天气泡。颜色就是用来把它们和用户行分开的。

## 展开后的正文

正文是这条将要发送的字，再附上工具名、参数、结果和图片路径。后台进程结束那条在面板里只显示「后台进程已结束」，不把整段运行时标注铺开。模型实际收到的那条见 [系统提示](./系统提示.md)。

**message id。** 只有普通用户行的 id 可点，点了复制，并提示「已复制 message id」。用来跳回会话里的那一条。其它行的 id 只展示，不能点。合成出来的驻留 id 不能拿去当跳转锚点。

**阅读优化。** 开关只出现在驻留行，并且正文能拆成分段时。整个面板共用一个开关，不是每行一个。打开后，这些驻留行按分隔章节显示。不改发给模型的正文，也不改导出。

## 勾选与变淡

除工具结果外，每行都能取消「下一发带上它」。取消会记住，下次打开还在。

- 取消一次用户开口：这一回合里它后面的助手、工具调用、工具结果一起不发，并一起变淡。
- 取消一次工具调用：紧跟的工具结果一起不发，并一起变淡。
- 变淡是整行透明度 0.45。勾回去就恢复。

统计条上的「发送」token 跟着这些勾选变。磁盘上的会话原文不改。

## 统计条写什么

一行：

```
消息 {条数} 条 · 对话轮次 {回合数} · 原文 {token} / 发送 {token} tokens
```

条数是窗口截断之后、还没按勾选丢掉的列表长度。回合数按截断前的对话回合计。原文是完全不去细节、不压、不切窗时的历史，加上固定开销。发送是勾选之后真正会放进请求的历史，加上固定开销。本地按码点估算，不必等于供应商账单。

若底栏占用账本已经落座，且和这次实算的占用不一致，下一行用错误色写：

```
落盘 {账本} · 实算 {占用} · 差额 {实算减落盘}（仅发送，未回写）
```

这里的实算是压完、去细节完、还没按勾选丢掉之前的占用，不是统计条上那个跟着勾选变的「发送」。差额只显示。打开这个面板不把实算写回账本。

路径上还有成功的旧压缩胶囊时，再写「已命中压缩边界（摘要起算）」。驻留里能数出至少两段整合文本时，再写「整合段 N」。

底栏圆环只显示占用，超过窗口 90% 变红。它信账本，不信这个面板刚算出来的数。聊天里「可视化推出」把窗外的原消息变淡，那是另一套 id 集合，详情列表里根本不会出现已经被窗口切掉的旧原文。

## 列表是哪一份

每次打开才从磁盘全量重放，和真正生成走同一套投影：选中分支、同一套工具协议行、同一套去细节化、同一份驻留、再按「窗口减固定开销」从新往旧切。不要为面板另写一份「差不多的历史」。

切窗时，一次工具请求和它后面的全部结果是一块，不拆开。至少留下一条真实用户消息；单条用户输入已经超过预算时也留下它。切完后若开头是助手或工具，丢掉那一截，从第一条真实用户消息起。

面板列出的是切完后的结果。被切掉的旧原文不在列表里。

## 导出

下载把这一次的详情写成 JSON，放进系统 Download。文件名：

```
agora_context_{会话id}_{yyyyMMdd_HHmmss}.json
```

会话 id 里的路径符号和空白换成下划线。还没有会话 id 时，中间那段是 `new`。成功提示「已导出到 Download/{文件名}」。

文件是一个数组，第一项一定是系统：

```json
[
  { "role": "system", "content": "…" },
  { "role": "user", "content": "…", "id": "真实用户消息 id" },
  { "role": "assistant", "content": "…" },
  { "role": "tool", "content": "tool: …\nargs: …" },
  { "role": "tool_result", "content": "…" },
  { "role": "compact", "content": "…" }
]
```

`id` 只出现在普通 `user`。驻留导出的 `content` 不是面板上那份阅读优化正文，而是线上正文，并带上从磁盘回合重建的原文对照。阅读优化不影响导出。对照里的工具结果是归档前的全文；面板上那一行即使已经是 `detail_ref`，导出对照里仍是全文。后台进程那条在导出里是 `—`。

要评测，用这份 JSON，不要去爬界面。只要模型看见的字，读 `role` 和 `content`。
