# 上下文压缩机制（按批归档 + 工具去细节化）

Status: **已由 [`context-compact-summary.md`](context-compact-summary.md) 取代**（2026-08-31）。下文为历史按批归档设计。  
**时间分层与测试期归档带** 见 [`context-compact-time-bands.md`](context-compact-time-bands.md)。当前测试期走达阈后的批次 / Digest 投影；整合带关闭。  
归档带内部的 Digest 工作上下文见 [`context-compact-digest.md`](context-compact-digest.md)。本文仍是组批、锁定、预压缩与去细节化的基线。  
取代：`context-compact-requirements.md` 所述的「整段前缀一次压缩 + 胶囊内嵌最近 N 条原文」模型。  
曾用名：按轮归档；现改为**合批总结压缩**，并以**工具去细节化**作为发送路径上的另一类压缩手段。

---

## 0. 两种压缩手段（关联但不是同一件事）

本体系里有两种都会缩小「发给模型的上下文」的手段，**都叫压缩范畴内的手段**，但机制不同，必须分开实现、分开表述：

| | **工具去细节化**（去除细节） | **总结式压缩**（按批归档） |
|--|------------------------------|---------------------------|
| 作用对象 | 单次**工具调用结果**（长输出） | **连续多轮对话**（一批） |
| 做法 | 原文写入细节库；API 投影换成短 `detail_ref`（摘要 + 细节 id） | 整批原文写入细节库；达阈后投影换成**批次摘要 + `batchId`** |
| 是否调用大模型总结 | **否**（摘要多为规则/UI 同款一行） | **是**（内置提示词合批总结） |
| 触发 | 发送前对历史工具结果做投影预处理（当前轮 live 除外） | 满批预压缩 / 达阈正式压缩 |
| 细节库键 | 工具级 id（通常为 `toolCallId`） | **`batchId`** |
| UI | 会话仍显示工具原文 | 会话仍显示对话原文 |
| 读回方式 | `query_detail_store(detail_id)` | 用 `batchId` 查整批原文 |

**关系：**

- 去细节化是**细粒度、发送路径**上的压缩：先把易膨胀的工具载荷从模型上下文里摘掉。
- 总结式压缩是**粗粒度、达阈后**的压缩：把多轮对话收成摘要，并保留跨轮逻辑。
- 总结式压缩的输入必须是**会话原文对象**（工具结果为全文），**不能**建立在已去细节化的 `detail_ref` 之上。
- 某一批一旦完成总结式压缩（整批原文已按 `batchId` 入库），该批内此前产生的**工具级细节条目应删除**，避免与批原文重复存储、细节库膨胀。

二者共用（或可共用）物理「细节库」，但键空间与生命周期不同。

---

## 1. 目标

- 工具长输出撑爆上下文 → **去细节化**：历史工具结果变 stub，原文可回查。
- 单轮总结易切断相邻轮因果 → **合批**总结，一批一个 `batchId`。
- 可自定义压缩提示词质量不稳 → **去掉**用户可编辑压缩提示词，改为内置。
- 达阈后串行压太多 → **满批异步预压缩**，达阈尽量命中。
- 双份存储膨胀 → 批次落库后**回收**批内工具级细节。

## 2. 核心概念（总结式压缩）

### 2.1 一轮对话（Turn）

**定义：** 从进入该轮起，到模型**不再调用工具并返回终态**为止，算一轮结束。

与现有 UI 对齐：一轮结束时出现操作按钮行（复制、分享、分支、锁定等）。**轮**是组批、锁定与尾部保留的计数单位。

### 2.2 轮 ID（`turnId`）

每轮稳定 ID，一经生成不变。用于轮身份、锁定锚点、组批成员列表。  
**不是**批次细节库键，也**不是**工具去细节化的检索键。

- 分支切换 / 重发 → 新轮新 `turnId`；旧 id 留在原图位置。

### 2.3 压缩批次与批次 ID（`batchId`）

- 单位：连续、**未锁定**的已结束轮，上限 **B**（默认 **8**，可设置）。
- 每批一个 **`batchId`**：预压缩缓存键、批细节库键、达阈后上下文显式抛出的细节 id。
- 批内各轮**原文**合入**一条**细节；模型凭批次摘要决定是否用 `batchId` 回查。
- 原则：约 B 轮常同一话题；尾部保留原文轮数也取 **B**（与批大小同一设置或默认绑定）。

### 2.4 锁定

文档与实现下文均称**锁定**。

**全称：总结式压缩锁定。** 含义：对该轮**总结式压缩不生效**（不入批；达阈后仍以原文进入上下文）。  
**不**表示关闭工具去细节化，也**不**表示冻结该轮一切压缩相关行为——历史工具结果仍可按 §3 变成 `detail_ref`。

- UI：每轮结束操作行增加锁定开关；点击开/关。
- **仅当该轮尚未进入任何已生效总结式压缩批次时**可改；已入批则去除或禁用按钮，不处理事后加锁/解锁，不作废重切。

### 2.5 原文对象 vs API 投影对象

| | 原文对象 | API 投影对象 |
|--|----------|----------------|
| 持久化 / UI | 会话真实内容（工具全文） | 不替代 UI |
| 去细节化 | 不改 Room 原文 | 历史工具结果 → `detail_ref` |
| 总结式压缩 / 预压缩输入 | **只读原文**（工具须为全文） | 不用 stub 当输入 |
| 达阈前发给模型 | — | 轮次原文 + 可对历史工具去细节化 |
| 达阈后已压缩批 | 原文仍在会话；批原文在细节库 | 「批次摘要 + `batchId`」 |

## 3. 工具去细节化（去除细节）

### 3.1 定义

将指定工具调用的**长结果原文**写入细节库，在 **API 投影**中替换为短引用：

```text
detail_ref = { type, detail_id, tool, summary, hint }
```

- 会话 UI / Room **仍保留原文**。
- 当前用户消息之后的当轮工具环（live tail）**不去细节化**，模型当轮仍见全文。
- 这是压缩手段之一，但**不是**总结式压缩，也不调用总结模型。

### 3.2 适用范围（工具名）

| 纳入 | 说明 |
|------|------|
| `web_search` / `openai_search` / `google_search` | 搜索结果列表长 |
| `web_fetch` | 页面正文长 |
| `execute_local_command` | 本机命令输出长、有时效 |
| `execute_remote_command` | 远程命令输出长、有时效 |

首批不强制纳入：短结果工具（如 `list_remote_shells`、job 查询等）。

### 3.3 失败结果：不去细节化

工具**调用失败**的结果通常已很短，去细节化无收益。

| 情况 | 是否去细节化 |
|------|----------------|
| 结果 JSON **顶层存在 `error`**（含 `web_*` 失败、shell `jsonError`：拒绝执行、无 backend、缺参等） | **否**，投影保留原文 |
| 成功长输出（含 shell 带 `output` / `exit_code`，**即使 exit ≠ 0**） | **是**（命令非零退出仍是长结果，不是框架级失败） |

### 3.4 细节 id

- 优先使用稳定的 **`toolCallId`**（消毒后）作为 `detail_id`，与 stub 内字段一致，便于模型回查。
- 缺 id 时的行为应可观测、可测试，避免 stub 为随机 id、模型却用 `call_…` 查询导致 `not_found`（已知风险，实现须对齐）。

### 3.5 摘要

`summary` 与会话里该工具完成时的一行摘要同逻辑（搜索条数、fetch URL、shell 命令/退出码等），便于模型扫读而不必回查。

### 3.6 与总结式压缩的衔接（删除工具级细节）

当某一对话批次**完成**总结式压缩（预压或正式压缩已将整批原文写入 `batchId` 细节）之后：

1. 批内各轮原文（**含工具全文**）已在 `batchId` 条目中；
2. 必须**删除**该批内此前去细节化产生的**工具级**细节条目；
3. 之后回查只依赖 **`batchId`**，不再保留工具级副本。

否则同一段 `web_fetch` / shell 输出会存两份，细节库持续膨胀。

| 情况 | 工具级细节 |
|------|------------|
| 仅去细节化、轮尚未入批 | **保留**（达阈前模型仍可能按 tool `detail_id` 回查） |
| 批次预压/正式压缩已落库 | **删除**批内相关工具级 id |
| 锁定轮 / 尾部未压缩原文 | **不删**其工具级细节（锁定不阻止去细节化） |
| 失败未去细节化 | 无工具级条目 |

成批时应能列举本批工具级 `detail_id`（扫原文/投影中的 `detail_ref`，或去细节化时登记），再对细节库做幂等删除。

### 3.7 `query_detail_store`：省略后续返回（不是去细节化）

`query_detail_store` **不**写入细节库（载荷本来就在库里；再 stub 成 `detail_ref` 会膨胀并诱导重复查询）。

| 情况 | API 投影 |
|------|----------|
| 当轮 live tail（最后一条真实用户消息及之后） | 成功返回保持全文 |
| live 之前的成功返回 | 换成一句说明（JSON `type=detail_store_omitted` + `detail_id` + `note`）；`tool_call` / `tool_result` 协议行保留 |
| 失败返回（顶层 `error`） | 保持原文 |
| 已是 omitted | 不再改写 |

## 4. 总结式压缩：行为规则

### 4.1 未达压缩阈值

- **不**把历史轮换成批次摘要。
- 发送路径仍可对历史工具做**去细节化**。
- 允许**满批预压缩**（见第 5 节）；预压结果不发给模型，直至达阈投影启用。

### 4.2 达到阈值之后

- 尾部最近 **B** 轮：原文（工具结果可按去细节化规则处理 live 之外的历史）。
- **锁定轮**：总结式压缩不生效 → 始终以**原文**入上下文，**不入批**；去细节化仍可按 §3 作用于其中的历史工具结果。
- 更早未锁历史：已入批者 → **批次摘要 + `batchId`**（id 显式抛出）。
- 必留信息过多顶满：可接受。

### 4.3 组批与锁定切割

锁定为总结式组批的**硬屏障**（只影响是否入批，不影响去细节化）。可压缩前缀（去掉尾部 B 轮）从旧到新：

1. 累积连续未锁定且未入批的轮；
2. 遇锁定 → 先收批，该轮保留原文，再重新累积；
3. 满 **B** → 新 `batchId`；
4. 末尾 **&lt; B**：预压不发；正式压缩（达阈/全量重压）允许不满批。

示例（`L` = 锁定，B = 8）：

```text
T1..T5  L  T6..T13  T14..T21(尾部保留)
```

- BatchA：`T1..T5`（不满批 → 仅正式压）
- `L`：原文（总结式压缩不生效；工具仍可去细节化）
- BatchB：`T6..T13`（可预压）
- `T14..T21`：原文

### 4.4 锁定 — 仅入批前可改

规则见 §2.4：仅未进入已生效总结式压缩批次时可改；已入批则 UI 不可操作，不事后重切。

### 4.5 合批总结时的上文（已废止「带 prior L2」）

跨批整合改由 Digest（会话摘要）负责，见 [`context-compact-digest.md`](context-compact-digest.md) §13。

**规则：调用批次总结模型时，只附本批原文（工具结果为全文），不附更早批次短摘要、不附活跃记忆/默认提示词、不挂细节库工具。**

某一批总结失败：不写入该批、不更新 Digest。

## 5. 预压缩（总结式，可选加速）

- **凑满 B 个**未锁定、适合预压的已结束轮后异步发起；不满批不预压；不阻塞对话。
- 推荐：只对已滑出尾部保留窗口的轮计入预压批。
- 输入：批内**原文**（工具全文，还原去细节化 stub）。不带更早批次 summary。
- 输出：批次摘要 + `batchId` 细节（整批原文）；持久化；达阈前不改变模型所见。
- 落库成功后：**删除**批内工具级细节（§3.6）。
- 达阈未命中预压：取消进行中的预压，立即正式压缩。
- 缓存键 = `batchId`。
- 锁定轮不进入预压批。

## 7. 内置提示词

- **总结式压缩**用内置系统提示：本批短目录、保留本批新增与未决；细节靠事后 `batchId`；**不要**要求承接更早批次摘要（跨批交给 Digest，见 digest 文档 §13）。
- 另有 **Digest / 会话摘要** 内置提示，见 digest 文档 §6.2。
- **默认系统提示前缀**（用户提示词之前）说明两套机制：  
  - 工具 `detail_ref` + 去细节化回查；  
  - 会话摘要（Digest）；写 Digest 时用闭集 `batchId`；锁定与尾部 B 轮原文（锁定语义见 §2.4）。
- 说明放在系统前缀，**不要**主要堆在工具 schema 里。
- **实现：** `AgoraSystemPrefix` 在编译工作模型 SYSTEM 时注入（正文中文，JSON 字段名仍为英文），不是 `DefaultSystemPrompt` 里可编辑的 Default。旧 Default 里烘焙的 `Context compression (Agora):` 段启动时剥离。细节见 digest 文档 §6.3。

## 8. 迁移与「重新压缩全部上下文」

- **重新压缩全部上下文 / 全量重新压缩**：按本策略对原文重新组批；旧 `compact_*` 会话自动全量重压后可用。
- 重压写入新 `batchId` 后，按 §3.6 回收工具级细节；退役旧胶囊边界。
- 全量重压时每批总结**只看本批原文**（§4.5）；全部批成功后再重建 Digest。
- **更新会话摘要**（仅 L1、不清批次）见 digest 文档 §16，与本条不是同一操作。

## 9. Provider 投影公式

**达阈前（可含去细节化）：**

```
[内置系统前缀：机制说明] + [用户系统提示] + [活跃记忆] + [技能目录]
+ 历史轮原文（历史工具结果可为 detail_ref）
+ 当前轮 live：工具全文
```

**达阈后：** 以 [`context-compact-digest.md`](context-compact-digest.md) §3 为准（会话摘要 / Digest；无 Digest 时 fallback 各批摘要 JSON）。锁定轮与尾部 B 轮仍为原文。工作模型 JSON 不带 `notes`。

## 10. 非目标

- 用户可编辑总结式压缩提示词。
- 用 `turnId` 作为批细节 / 预压缓存键。
- 压缩后再改锁定或重切已有批次。
- 将「锁定」理解为关闭去细节化或冻结整轮一切压缩（全称与语义见 §2.4：仅使总结式压缩不生效）。
- 失败工具结果去细节化。
- 批次落库后仍长期保留批内工具级细节副本。
- 总结式压缩以 `detail_ref` 为输入。
- 压缩删除会话中的原文。
- 不满批发起预压缩。

## 11. 实现要点清单

**去细节化**

1. 范围：web 搜索/fetch + `execute_local_command` / `execute_remote_command`。  
2. 顶层 `error` → 跳过；补齐 shell 摘要。  
3. `detail_id` 与 `toolCallId` 对齐；排查 `web_fetch` `not_found`。  
4. 仅改 API 投影；UI/Room 保留原文；live tail 不去细节化。

**总结式压缩**

5. `turnId` + 锁定（§2.4；仅未入批可改）+ 组批（B、锁定切割）。
6. `batchId` 预压/细节/投影；输入必须为原文。
7. 批次落库后删除批内工具级细节。
8. 设置 B（默认 8）；移除自定义压缩提示词；内置提示 + 系统前缀说明两套机制。
9. 全量重压 + 旧会话迁移；退役旧胶囊。
