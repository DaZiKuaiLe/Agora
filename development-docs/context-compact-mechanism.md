# 工作上下文压缩：落地机制（给另一端客户端）

Status: **现行实现**，2026-09-07。  
读者：要在另一个接入大模型的客户端里复用这套思路的人。  
Agora 内部一页合同仍是 [`context-compact-summary.md`](context-compact-summary.md)。按批 Digest、时间三带、旧胶囊只作历史。

本文写的是**已经落地的行为**，不是设想。另一端不必抄类名或 Room schema，但应保住分层、单位、达阈、增量追加、全量回放这几条。

---

## 1. 问题

对话原文会无限增长，模型上下文窗口不会。常见错法：

- 把磁盘上的历史删掉或改写成摘要（用户看不见原文，也无法搜索）。
- 每次发送都把全量历史再估一遍 token，当作「有没有超窗」的正确性检查（长会话的发送握手会卡死）。
- 把工具 stdout、网页正文和对话正文同等对待，全部塞进摘要模型。

落地做法：**磁盘永远是全文；发给工作模型的是一份只读投影；压缩是给投影用的，不是给用户记录用的。** 详情面板是这份投影的审计面：[`context-detail-panel.md`](context-detail-panel.md)。

---

## 2. 三层，不要混

| 层 | 存什么 | 谁维护 | 禁止 |
|---|---|---|---|
| **磁盘** | 选中分支上每一轮的原文（含工具调用全文） | 持久化库 | 压缩成功后删原文、用摘要覆盖原文 |
| **内存 / UI** | 图指纹 + 增量行 + 一条「下一发占用」账本 | 只对变更行拉盘；账本只加一回合 | 用内存再做一遍全量正确性校验 |
| **工作模型请求** | 系统前缀 + 人设 + 活跃记忆 +（若已压过）一条驻留正文 + 最近 B 轮原文 + 本轮 live | 发送前只读投影 | 把 UI 列表、流式 overlay 当成请求路径 |

三条推论：

1. 用户界面始终能滚到早期原文。压缩失败、跳过压缩、换模型，都不丢记录。
2. 占用条和「要不要压」只信已落座的增量账本。账本对不上时**不要**为了算对去扫全文；全量重算是详情页 / 审计路径。
3. 投影可以错、可以滞后；磁盘审计会纠正。发送热路径不负责纠正。打开详情只显示差额，不把实算写回账本。

---

## 3. 单位是「已结束回合」，不是消息条

**回合** = 一次真实用户开口，直到下一次真实用户开口。中间的助手、工具请求、工具结果都算同一回合。

- 半轮、正在生成的尾巴（live）**不进驻留、不占保留窗口预算**。
- 合成行（投影里的驻留行、批次行、图片上下文等）**不是**新回合。
- 保留窗口 B 是「最近 B 个**已结束**回合原文」，默认 8，可配。

不要按「最近 N 条消息」切。一条助手回复里可能有很多工具轮次，切开会把一次任务拆碎。

---

## 4. 工作模型实际看见的

```
[系统前缀 + 人设 + 活跃记忆 + 工具定义]     ← 固定开销，计入窗口，不进驻留
[驻留正文]                                 ← 可选；纯文本，不是 JSON
[最近 B 个已结束回合的原文]
[本轮 live]
```

驻留是**一条**用户角色的纯正文（实现里合成 `context_digest_*` 这一行）。多段历史在存储里用分隔符拼，上线时加「整合段 1/N」头。各段都是当时折出来的历史，允许口径不同或轻度重复，工作模型按时间先后读。

没有压过的对话：没有驻留行，整段都是原文，再受窗口预算截断。

旧版「Compact 胶囊消息」只在还没有任何批次痕迹时，作为祖先链上的上下文边界。有批次 / 驻留之后应卸掉胶囊，不要两套边界并存。

---

## 5. 两件正交的「变小」

### 5.1 工具去细节化（不调用摘要模型）

把历史上过长的工具结果换成一句卡片摘要 + `detail_ref`（`detail_id`）。原文进细节库。失败的短错误、非归档工具，保持原样。

`query_detail_store` **只**服务于这些工具载荷。对话里说过的话不走细节库。

### 5.2 回合压缩（调用压缩模型）

把保留窗口之外、尚未折进驻留的已结束回合，交给压缩模型，得到新的驻留段。

**压缩模型必须吃工具全文，不能吃 `detail_ref`。** 去细节化发生在「给工作模型的投影」上；压缩输入从磁盘组装，不经过 stub。

---

## 6. 什么时候压：量窗外未折叠原文

触发量的是：

```
token(保留窗口之外、尚未 batched 的已结束回合原文)
+ token(系统提示 + 工具定义等固定开销)
```

**不是**投影后的总占用（驻留已经很短，总占用会低估「还有多少原文没折」）。  
**也不是**占用条上的数字本身（占用条含保留窗口原文）。

未达阈：不压。  
窗外已经全部 batched：不压。  
回合数还不超过 B：不压。

交互发送达阈：弹窗（压缩再发 / 本次不压仍发 / 取消）。  
自动化路径：静默压；失败则本轮不发。

不要预压写中间稿。不要在发送握手里为了「确认阈值」去全量重估。

---

## 7. 增量折叠：只压新滑出的，旧驻留追加保留

已结束回合从保留窗口滑出，且未折叠原文再次达阈：

```
新章 = compress(刚滑出窗口的未折叠原文)
驻留 = 旧章… + 新章
滑出的那些回合打上「已覆盖」标记
最新驻留写在最新年覆盖回合上
```

要点：

- **不要**把旧驻留再送进压缩模型重写一遍。每折一次旧文会丢一次信息。
- **不要**把活跃记忆、人设写进驻留。它们每次请求已经在系统侧出现；写进去会变成第二份世界观，和磁盘冲突时说不清谁算数。
- 压缩输出超长或窗口溢出：把本批回合对半切开再试。单回合仍放不下 → 失败（这一回合太大，不能假装成功）。
- 压缩模型的 `maxTokens` 用「冻结阈值」（默认 256K），与工作模型的回复上限分开。这是单章篇幅帽，不是「把旧章改写成不超过帽」。

压缩文笔（应写进压缩系统提示，而不是事后用 JSON schema 约束）：

1. **个人**：用户本人、亲友、情感、日常、经历、和模型一起得出的独创结论 → 近无损，只整理句式。
2. **工程**：只留已确认事实与现行方案；工具调用是过程不是目的；作废尝试一句带过。
3. **通识**：可以只记「曾经问过」；不得因此丢掉原则 1、2 的内容。
4. 不要 JSON、不要「以下是总结」、不要翻译、不要对用户说话。语言跟对话走。

---

## 8. 全量优化：从原文回放，不拿旧驻留当输入

在这些情况下必须从磁盘原文重做驻留：

- 用户明确点「上下文全量优化」；
- 会话已经有压缩痕迹，但投影/压缩契约版本落后（`compactFormatRev < CURRENT`）。

做法：

1. **按当年「每发一次会不会达阈」的节奏回放原文**。每当未覆盖前缀跨过阈值，把那一段单独压缩成一章，然后丢掉。不要先把整段对话的工具 JSON 全部拆进内存。
2. 回放结束时仍低于阈值的尾部保持原文。最近 B 轮也保持原文。只把这些留下的轮里、指定工具的成功长结果写入细节库（原文仍在盘上，不改 Room / 会话 UI）。已经收成章的轮不另写一份工具级副本。
3. 新章提交成功后才忘掉当前驻留。失败则旧驻留还在。
4. 把会话上的契约版本写成当前值。

机制变了才把 `CURRENT_REV` 加一（投影形状、压缩输入变了）。用户改活跃记忆或默认提示词不加。没有压缩痕迹的对话不弹「请先优化」。

交互路径：落后则发送前必须确认，可暂缓（暂缓就不发）。自动化路径：静默全量，失败则本轮不发。

---

## 9. 发送热路径：账本，不是审计

占用与「要不要自动压」落在会话级账本上：

- 已落座：相信 `下一发占用` 和 `窗外未折叠原文 token`。
- 新结束一回合：只给账本加这一回合的增量；滑出保留窗口且未覆盖的，加到「未折叠前缀」。
- 配置变了、压缩签名跳了、从未落座：热路径**不要**为了算对去加载全文。跳过自动压，或等详情投影把账本重新落座。

格式是否过期：读会话上的契约版本 + 磁盘上是否已有压缩痕迹（批次标记 / 驻留 / 旧胶囊）。这是元数据，不是把全部 `thoughts` 和工具 JSON 拉起来估 token。

真正开压之后才允许全量装路径——那是在做压缩工作，不是在做发送前的正确性检查。

## 10. 取回

| 用户要的 | 走哪 |
|---|---|
| 「我们上周怎么说的」 | 对本会话**磁盘原文**做搜索（关键词即可；不要指望驻留里还有原话） |
| 「那次 web_fetch 的全文」 | `query_detail_store` + 当时的 `detail_id` |
| 「驻留写错了」 | 看 UI 原文；必要时全量优化从原文重写 |

不要让工作模型用搜索去「证明」投影正确。投影错了，修投影或全量优化。

---

## 11. 另一端最小复现清单

可工作的最小集：

1. 持久化全文 + 每回合稳定 `turnId` + 「是否已覆盖」标记 + 一份驻留正文（可多章拼接）。
2. 投影：有驻留则窗外已覆盖回合换成那一条正文，否则原文；加上 B 轮原文和 live。
3. 达阈：只估窗外未覆盖原文 + 固定开销。
4. 增量：只压缩新滑出的未覆盖原文，结果追加为一章。
5. 全量：从原文按阈值节奏切片重压，bump 契约版本。
6. 发送：交互达阈先问；热路径不扫全文。
7. 工具长结果单独归档；压缩输入禁止用 stub。

可以后做：占用条增量账本、可视化窗外变暗、专用压缩模型、多分支。

不要做：删原文、把 UI 当请求、把旧驻留反复重写进模型、用总占用当压缩阈值、发送时全量重估 token。
