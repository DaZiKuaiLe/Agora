# 上下文压缩：时间分层（原文带 / 整合带 / 归档带）

Status: **已由 [`context-compact-summary.md`](context-compact-summary.md) 取代**（2026-08-31）。下文为历史时间分层设计。  
读者对象：实现与提示词修订。文档还会改，本文只整理目前已对齐的理论。  
颗粒度三层（索引 / 中间稿 / 细节库）的历史实现见 [`context-compact-digest.md`](context-compact-digest.md)。组批、锁定、去细节化物理层见 [`context-compact-turn-archive.md`](context-compact-turn-archive.md)。

---

## 0. 要解决的问题

现网总结式压缩对**所有已压轮**用同一套力度（短 Digest / 短 L2）。长会话里会出现：压缩前缀比系统提示词还薄、专有名词被合并掉、模型无法发现该去细节库查什么。这是策略过狠的症状，不是「Digest 必须厚过 Default」这种目标。

另一维被忽略了：**离「现在」越近，窗口里该留得越厚**；越久远，驻留越不值（就算能无损取回，也要 API 次数和等待）。1M 窗口里，前面几百 K 往往是很久以前的题，当历史去查即可。不按时间分层，就会出现「远处刚好、近处损失大」或反过来。

---

## 1. 两个正交维度

不要把两套「三层」混用。

| 维度 | 名称 | 问的是 |
|------|------|--------|
| **时间** | 原文带 / 整合带 / 归档带 | 这段对话有多近，上下文里留多厚 |
| **颗粒度** | 仅作用于**归档带内部**：L1 索引、L2 中间稿、L3 细节库 | 留下的是发现用的键、作者用的脉络，还是库里的原文 |

高保真抽取（保检索键、L2 要有脉络）是归档带的写法和粒度问题。时间分层决定 **要不要还呆在窗口里**。

---

## 2. 时间三带

工作上下文从近到远：

```
SYSTEM
归档带：digest / 关键词可发现的历史（本测试期开启）
整合带（测试期关闭）
原文带：最近 B 轮原文（默认 8，跟现有 retain / 批大小设置）
本轮 live
```

锁定轮：总结式压缩锁定仍表示「不入归档批」。测试期建议锁轮 **留在原文带**，不强制整合。

权威顺序（同一事实只认最近一层）：

1. live、原文带、锁定原文  
2. 整合带（测试期不投影）  
3. 归档带 digest  
4. 活跃记忆 / Default  

### 2.1 原文带

保留对话原文。工具成功长结果仍 **去细节化**（发送路径去冗余）：高成本、对后续几乎只有载荷意义的全文先摘掉；live 尾部仍见工具全文。这不是总结。

### 2.2 整合带（理想的驻留压缩；本测试期关闭）

**按轮、不合批。** 一轮已包含整段工具环。目标是窗口里的近无损改写（设计意图像 PNG，不是物理无损）：

- 去除多余表述，用更短更准的语言复述；  
- **轮内**归并同类信息；跨轮合并过时事实 **不是** 这一带的职责（留给归档带）；  
- 工具协议不留在时间线里：改为一句总括（调过哪些、有没有、量级）。有用结论写进整合正文。空搜若会约束以后别再用同一查询，留这一句即可；  
- 正文挂 **原文 `turnId`**，需要原文时精确 `query_detail_store`（测试期在整合成功后把该轮原文写入细节库，键为 `turnId`）；  
- 出网与上下文详情：**连续**已缓存的带外轮收成 **一条** user，`type=turn_integrations`，`turns` 数组从旧到新。不把 `origin` 放进发给模型的 JSON；导出时每项附带该轮原文。  
- Room / 会话 UI **仍是原文**，只改 API 投影。

整合是 **尽力而为的优化**：不阻塞发送、不弹「压缩上下文」窗、允许滞后（带外几轮仍是原文、甚至交叉）。不精确锁定。理论上门外几轮原文不妨碍理解，只是窗口更大。

### 2.3 归档带（改意；本测试期开启）

给「一场会话聊太久、话题太多、一直不关」做保险，不是日常主压缩。

相对现网短 Digest：

- 工作模型 **不当** 窗口里的完整世界观短文；几乎要舍弃驻留，当档案。  
- 真需要时用 **关键字 / 关键短语** 搜，而不是指望还记得 `batchId`。L1 是发现用索引（专有名词、结论、可搜的短语 + 号）；L2 是给 Digest 作者的中间稿，**要有基本脉络**，否则增量写 L1 时更早各批原文不在输入里，键会永久丢失。L2 可以较长：每批只写一次，贵的是改 L1 时闭集再喂完全部 L2。  
- 解压更贵（检索 → 再取原文），换窗口空间。  
- 现网「工作上下文只放一份 Digest、闭集抄号、不合批 L2 进工作模型」仍可作为归档带内部结构，但 Digest 文风从短现行状态改为高保真索引；检索从「只抄 digest 里的号」扩展到短语搜索（实现以后再定）。

## 3. 测试期范围（当前实现）

- **只开归档带**：达阈组批、写 / 投影 digest（无 digest 则 `summary_batches`）、发送前可因 `compactFormatRev` 或知识 rev 拦截。触发与整合落地前相同（token 阈 + 满 B 预压），不是「第 9 轮立刻压」。  
- **屏蔽整合带**：不写 / 不投影 `turn_integrations`。  
- 不 bump `CompactFormat.CURRENT_REV`。  
- 组批与投影按**对话轮**计数（与 retain B 对齐）；live 尾不占原文带预算。  
- 现有会话若已有整合缓存：测试期投影忽略它们。

### 3.1 生产与消费

| | 何时 | 做什么 |
|--|------|--------|
| 预压缩 | 滑出 retain 的未锁定轮凑满 B | 异步写该批 L2 与细节库原文；不改 Digest |
| 正式压缩 | 发送时未压缩前缀的 token 占用达阈 | 可含偏批；attach 后更新 Digest |
| 投影 | 发送与上下文详情 | 已入批且在 retain 之外 → 一份 `context_digest`（否则 `summary_batches`）；锁定与尾部 B 轮原文 |

归档模型用现有「上下文压缩」模型配置。走总结式压缩的会话 Mutex。

### 3.2 上下文全量优化（手动、可等待）

一次从旧到新的扫描，不先把整段对话的工具 JSON 全部拆进内存：

1. **整合带**：本测试期跳过。  
2. **归档带**：按达阈节奏从原文重放。每当滑出保留窗口的未覆盖前缀跨过阈值，把那一段单独送给压缩模型，然后丢掉。尾部低于阈值的保持原文。不得用整合文当归档输入。新章提交成功后才清掉旧批次。  
3. **原文带 / 去细节化**：只给这次留下的原文（最近 B 轮，以及没达阈的尾部）把指定工具的成功长结果写入细节库。按每几条读、写入、丢掉。不改 Room / 会话 UI 原文。已经收成章的轮不另写一份工具级副本。

全量优化会挡交互（进度遮罩），用压缩模型配置。

## 4. 明确不做（本文阶段）

- 短语检索（仍只抄 digest 里的 `batchId`）。  
- 同时打开整合带与归档带。  
- 用同步锁把带外轮全部变成整合再允许发送。  
- 改 Room 会话原文。  
- 把「L1 必须长过 Default」写成目标。  
- bump `CompactFormat.CURRENT_REV`。
