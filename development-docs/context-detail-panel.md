# 上下文详情面板：界面、机制、底层（给另一端客户端）

Status: **现行实现**，2026-09-07。  
读者：要做「下次究竟发给模型什么」调试面的人。压缩算法见 [`context-compact-mechanism.md`](context-compact-mechanism.md)。

详情面板是**审计面**，不是聊天记录，也不是底栏占用环。打开它才允许全量从磁盘重放投影；平时占用条只信增量账本。

---

## 1. 产品位置

用户要回答的问题是：**下一发（不含输入框草稿）会把哪些角色、哪些正文交给工作模型？**

不是：

- 会话 UI 里能滚到的全文（那是磁盘/UI 层，永远更长）；
- 底栏圆环上的占用（那是账本上的下一发估算，可以略错）；
- 「可视化上下文推出」的变暗（那是窗口截断后哪些**原消息 id** 还在窗内）。

入口：打开一个已有会话 → 顶栏 ⋮ → **查看上下文**。新会话、加载中、分享多选时菜单禁用。全屏 Dialog，返回键关闭，点外面不关。

底栏圆环只显示占用，并在超过窗口 90% 时变红；全量优化在工具菜单里，不走详情面板。

## 2. 界面怎么排

从上到下：

1. **顶栏**  
   标题「上下文详情」。副标题写明：下次发送交给模型的原文，不含草稿。左关，右导出（有数据且不在 loading 时才出现）。
2. **统计条**（一块浅底卡片，始终在列表顶）  
   - 投影后的消息条数、逻辑回合数；  
   - **原文 token / 发送 token**（见 §5）；  
   - 若已落座账本和这次实算不一致：用错误色写出落盘、实算、差额，并写明**只审计、不回写账本**；  
   - 路径上仍有旧成功胶囊时提示「已命中压缩边界」；  
   - 驻留若有 ≥2 个整合段，提示段数。
3. **SYSTEM 块**  
   生效系统提示（前缀 + 人设 + 活跃记忆等拼好的那一串）。空则显示占位。块上有这一行的估算 token。
4. **每条将发送的消息一块**  
   默认**全部折叠**。展开才出等宽正文。列表回收后折叠状态仍按 key 记住。
5. **空历史**  
   「当前没有可发送的历史消息」。
6. Loading 居中转圈；失败居中错误 + 取消。右侧淡入滚动条。

### 2.1 块的视觉

| 种类 | 角色条 | 色 |
|---|---|---|
| 系统 | SYSTEM | tertiary 容器 |
| 普通用户 | `#n USER · 轮 k` | 浅绿 / 深绿（随亮暗主题） |
| 助手 | `#n ASSISTANT` | surfaceVariant |
| 工具调用 | `#n TOOL` | error 容器 |
| 工具结果 | `#n TOOL RESULT` | 稍淡的 error 容器 |
| 驻留 / 旧胶囊 | `#n COMPACT SUMMARY` | secondary 容器 |

普通用户的 `k` 来自**导出源路径**上的对话回合编号（从 1），不是发送列表下标。投影合成行、工具行没有「轮 k」。

右侧小字：种类标签（压缩摘要投影 / 工具调用 / …）+ 本块估算 token。

### 2.2 展开以后

- **阅读优化**开关：只出现在压缩投影行，且正文能被解析成可读分段时。打开后把驻留 / 旧 `summary_batches` JSON 显示成分隔章节。**不改线上正文，不改进导出。** 开关是面板级一份，不是每行一份。
- **普通用户**：等宽 message id，点一下复制（给「跳转到对话」用）。其它行只展示 id，不可点。
- 正文：`assembleText()` + 若有 tool 则 `tool / args / result` + 图片路径列表。空白显示 `—`。

原则：默认折叠，因为真实请求可能极长；颜色分角色，压缩行和工具行不能长得像普通聊天泡；id 只给用户行可复制，避免把合成 `context_digest_*` 当成可跳转锚点。

## 3. 和占用条、变暗的分工

| 面 | 用户看见 | 算不算全文 | 何时全量扫盘 |
|---|---|---|---|
| 底栏圆环 | 下一发占用 / 窗口 | 否，信账本 | 账本落座失败、配置变、压缩签名跳、打开「可视化推出」时 |
| 可视化推出 | 窗外原消息变暗（α 0.38） | 要一份 retained id 集 | 只要开关开着，占用刷新就走全量 `project` |
| **详情面板** | 系统 + 截断后的请求正文 | **是，每次打开** | **每次打开** |

不要用详情面板的打开路径去刷占用条。不要用占用条的数字当详情里的「发送 token」。

打开详情**不会**把实算写回账本。差额只显示。纠正账本的是占用条那条 `NeedsFullRecompute` 投影，不是这个 Dialog。

## 4. 打开时的数据管道

每次 `conversationId / 模型 / 窗口预算` 变化，面板 IO 线程走同一套 `buildProviderContext`，再多做窗口截断和两种 token。

```
磁盘：选中分支的消息行
  → 拼上工具协议行（与真正生成同一套 assembler）
  → 工作模型可见正文（含转录策略）
  → 用户前后缀（若有）
  → 工具去细节化 stub          ← 工作模型路径；导出 origin 不用 stub
  → 时间带投影（驻留 + 最近 B 轮）
  → 固定开销 = 系统提示 + 工具定义
  → prepareMessages：按「窗口 − 固定开销」从新往旧切
  → 面板列表 = 系统块 + 切完后的消息
```

要点：

- **不含草稿、不含流式 overlay。** 和「下一发」一致。
- 只走当前选中分支。
- 系统/工具配置用「投影快照」，**不要求 Provider 已配好 key**（和真正开跑的 admission 快照不同）。
- 新会话没有磁盘行时，仍能预览将生效的系统提示（入口菜单通常进不来，投影层本身支持）。

四份列表不要混：

| 名字 | 是什么 | 谁用 |
|---|---|---|
| durable / original | stub、时间带、前后缀之前 | 「原文 token」 |
| export source | 前后缀之后、stub / 时间带之前 | 导出时给驻留挂 `origin` |
| projected | stub + 时间带之后、窗口截断之前 | 占用 usage、账本落座 |
| prepared | 再按预算截断 | 面板列表、「发送 token」 |

## 5. 三个（其实四个）token

本地估算器按码点估，和供应商账单不必相等。面板要让人看见**投影变小了多少**，以及**窗口还切掉了多少**。

| 数字 | 公式 | 含义 |
|---|---|---|
| 原文 | `estimate(durable) + 固定开销` | 若完全不 stub、不压、不切窗，历史有多大 |
| 占用 / usage | `estimate(projected) + 固定开销` | 压完、stub 完、还没按窗切 |
| 发送 | `estimate(prepared) + 固定开销` | 真正会放进请求的历史 + 固定开销 |
| 账本 | 会话行上落座的下一发占用 | 圆环用的；详情拿来对比 usage |

统计条上的「原文 / 发送」是表里第一行和第三行。账本对不上时对比的是账本 vs **usage**（切窗前），文案写明不回写。

固定开销含系统提示和当前工具定义，所以换工具开关、换人设、换活跃记忆都会让详情和圆环一起失效（圆环的 configKey 含这些）。

达阈压缩仍只看窗外未折叠原文，不看这四个数里的「发送」。不要在详情里用「发送即将满窗」去解释自动压缩弹窗。

## 6. 窗口怎么切（`prepareMessages`）

预算给消息的部分 = `窗口 − 固定开销`（至少 1）。

从**最新**协议单元往旧加：

- 工具请求和它后面的全部结果是**一个原子单元**，不拆。
- 必须留下一个真实用户锚（不是工具协议行）。单个用户输入已经超过预算时，仍然留下它。
- 切完后若开头是助手/工具，丢掉那截，从第一个真实用户起。供应商协议普遍要求用户开头。

切完后再合并连续同角色、去掉空轮。面板展示的就是这个结果，不是磁盘顺序全文。

可视化推出用另一套：在**未切窗的投影**上算哪些原 id 还留在窗内，回映射到聊天泡变暗。详情列表里不会出现「被切掉的旧原文」——它们根本不在 prepared 里。

## 7. 导出

顶栏下载把**当前这次**详情写成 JSON，进系统 Download。文件名 `agora_context_{会话id}_{yyyyMMdd_HHmmss}.json`。

形状：数组，第一项一定是系统。

```json
[
  { "role": "system", "content": "…" },
  { "role": "user", "content": "…", "id": "真实用户消息 id" },
  { "role": "assistant", "content": "…" },
  { "role": "tool", "content": "tool: …\nargs: …" },
  { "role": "compact", "content": "{…驻留包装…}" }
]
```

规则：

- `id` 只出现在普通 `user`。合成行、工具、助手不写 id。
- `compact` 的 `content` 不是面板上看到的纯正文。导出时用 export source **从磁盘回合重建 origin**：每个已覆盖 batch 带上当时的原文消息列表。工作模型线上仍是一条纯驻留；origin 只给对照、评测、别的客户端学习。
- **阅读优化不影响导出。** 导出永远是线上形状 + origin，不是分隔阅读文。
- origin 用 stub 之前的工具全文。若面板上该行已经是 `detail_ref`，导出 origin 里仍应是归档前的结果。

另一端若要做评测集：用导出 JSON，不要爬 UI。若只要「模型看见的字」：读 `role/content`，忽略 compact 里的 `notes/origin`。

## 8. 另一端最小复现

1. 一个只读全屏：「系统 + 下一发消息」，默认折叠，按角色上色。
2. 和真正 generate **同一套投影函数**（同一分支、同一 stub、同一时间带、同一截断）。不要另写一份「差不多的历史拼接」。
3. 打开才全量算；不要在输入、滚动、发送热路径上跑。
4. 统计至少两列：压缩/stub 前 vs 截断后。若你也有增量占用账本，差额只显示不回写。
5. 导出与屏幕分离：屏幕可有阅读优化；导出保持线上字节 + 可选 origin。
6. 不含草稿。工具轮次不拆。

可以后做：复制 user id、整合段数、旧胶囊提示、和占用环对账。

不要做：把详情打开当每次发送的正确性门闩；把详情结果写回占用账本；在详情里编辑历史并当成压缩。
